# 구조와 Rust 전환

## 실행 구조

`moasearch.exe`는 Rust Windows 데스크톱/CLI 앱이다. 기본 실행은 Tao 창과 Wry WebView2를 만들며 외부 브라우저를 열지 않는다. 정적 화면 파일을 실행 파일에 포함하고, 같은 프로세스의 Axum이 루프백 주소에서만 내부 화면과 API를 서비스한다. WebView는 해당 주소로만 이동할 수 있고 새 외부 창·다운로드·추가 권한은 허용하지 않는다. SQLite는 rusqlite bundled로, AI는 고정된 llama-cpp-2 소스의 llama.cpp를 네이티브 라이브러리로 연결한다. Python·Ollama·AI 서버 프로세스를 실행하지 않는다.

- `config.rs`: 저장 위치, 제외 경로, Windows 경로 정규화와 파일 속성 확인
- `store.rs`: Python 버전과 호환되는 SQLite 스키마, FTS5, 트랜잭션 카운터·변경 버전
- `extract.rs`, `ocr.rs`, `pdf.rs`: 텍스트·Office·HWP/HWPX, Rust ONNX OCR·Windows PDF 렌더
- `indexer.rs`: 단일 색인 작업, 취소, 증분 검사, 완료된 파일 배치 저장
- `search.rs`: 문자열·정확 코사인 검색, 파일별 최고 청크, RRF, 벡터·질의 캐시
- `models.rs`, `engine.rs`: 고정 Google 모델 다운로드·검증, 내장 추론
- `app.rs`, `main.rs`: 로컬 HTTP API·CLI·실행
- `desktop.rs`: Windows 창, WebView2, 창별 폴더 범위와 마지막 창 종료 처리
- `launcher.rs`: 탐색기 경로 인자 검증, 같은 데이터 위치의 앱 재사용·창 열기

기본 실행과 `desktop`은 전용 창을 연다. 탐색기의 `open-folder`는 앱 식별·데이터 위치·토큰을 확인한 뒤 `/api/window`로 폴더를 전달한다. 서로 다른 폴더는 독립된 창에서 검색하고 동일 폴더 창은 재사용한다. 마지막 창 닫기 또는 `/api/quit`은 색인을 취소·정리하고 서버와 창을 함께 종료한다. `serve`는 자동화 검증용 창 없는 개발 명령이다.

## 데이터와 모델 전환

기존 `settings`, `roots`, `files`, `chunks`, FTS 테이블과 `index_meta`를 보존한다. DB 경로는 이전과 같이 `%LOCALAPPDATA%/MoaSearch/index.sqlite3`다. Qwen 설정은 해제하고 기존 벡터는 새 Google 모델 ID와 격리한다. 본문은 계속 키워드 검색에 사용할 수 있으며, 재색인 시 Rust 리더와 Google 임베딩으로 교체한다.

EmbeddingGemma 2는 `task: search result | query: ...`와 `title: none | text: ...` 형식을 사용한다. Google Gemma 4 E2B는 검색된 구간에 번호를 붙인 문서 기반 답변을 생성한다. 모델별 SHA-256·버전을 고정하며, 사용자가 지정한 경로라도 승인된 Google 파일인지 새로 로드할 때마다 확인한다. 상태 화면은 파일 크기·형식의 기초 검사 결과를 표시한다. 대화 모델과 임베딩 모델을 번갈아 메모리에 유지한다.

## 색인·검색

DB 연결을 재사용하고 완료된 파일을 최대 32개·256청크·약 4 MiB 기준으로 저장한다. 파일 사이에서 0.5초 경과도 확인한다. 추출·임베딩 동안 쓰기 트랜잭션을 잡지 않는다. 취소 시 현재 파일을 버리고 완료된 파일만 저장한다. 취소하거나 폴더 접근 오류가 있으면 삭제된 파일 정리를 하지 않는다.

파일·청크 수와 변경 버전은 트리거로 같은 트랜잭션에서 갱신한다. 캐시는 모델·차원·읽기 스냅샷의 DB 버전으로 식별한다. 최대 128 MiB 정규화 벡터 캐시와 최근 질의 64개의 임베딩을 재사용한다. 캐시 한도를 넘으면 작은 블록과 상위 파일 힙으로 정확 검색한다. 근사 검색은 사용하지 않는다. 파일 경로 FTS5와 본문 인덱스는 추가 디스크 공간을 사용한다.

## 추출과 접근 경계

문서는 최대 200,000자, 파일 크기는 기본 32 MiB다. Office/HWPX는 ZIP·XML, HWP5는 CFB·제한된 deflate로 읽는다. XML 외부 엔티티를 처리하지 않는다. PDF는 lopdf 텍스트 추출을 먼저 적용하고 필요한 페이지만 Windows.Data.Pdf로 렌더하여 OAR/ONNX Runtime에 전달한다. 이미지도 같은 전용 OCR 모델로 읽는다. 모델 준비 상태를 앱과 doctor에 표시한다. Windows.Media.Ocr는 MSIX 패키지 identity 요구와 일반 실행 파일의 초기화 문제로 채택하지 않았다.

등록한 경로 밖과 자격증명·시스템 경로를 제외하고, 재분석 지점·심볼릭 링크·온라인 전용 파일을 따라가지 않는다. 파일을 읽기 전 경계를 다시 확인하고, 읽은 뒤 크기·수정 시각이 바뀌면 다음 색인으로 미룬다. 원본 파일은 수정하지 않는다.

HTTP API는 호스트·Origin·실행마다 바뀌는 토큰을 확인하며 본문 크기를 제한한다. 파일 열기는 색인된 범위와 안전한 문서 확장자를 다시 검증한다. 모델이 원문 내 지시를 따라 도구를 호출하거나 원본을 바꿀 권한은 없다. 토큰·문서·질의는 외부로 전송하지 않는다.

## 이전 개발 기록

1~14단계는 Python 기반 초기 구현, 내장 모델 실행, HWP/OCR/PDF 지원, 대량 파일 성능 개선 단계였다. 해당 구현과 테스트는 Git의 `7ee31b4` 및 이전 커밋에서 확인할 수 있다. Rust 전환 후 실행 경로와 테스트는 Cargo로 일원화한다. 단계별 검증과 한글 커밋을 계속 사용한다.
