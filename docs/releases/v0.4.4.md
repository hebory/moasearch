# 모아검색 v0.4.4 — 긴 본문 색인 종료 오류 수정

긴 본문을 색인할 때 모아검색이 갑자기 종료되는 오류를 수정했습니다. 같은 임베딩 경로를 사용하는 긴 자연어 검색어에도 적용됩니다.

**원인:** EmbeddingGemma 2 Q8_0 입력은 기본 최대 4,094토큰을 허용했지만 물리 배치 용량은 512토큰이었습니다. llama.cpp encoder는 입력을 microbatch로 나누지 못하므로, 512토큰을 넘으면 네이티브 assertion으로 앱 전체가 종료됐습니다. 설치된 v0.4.3에서 가상의 긴 한국어 본문으로 동일한 종료 코드 `0xc0000409`와 assertion을 재현했습니다.

- 접두어를 포함한 토큰화·잘림 후 가장 긴 실제 입력에 맞춰 임베딩 배치와 microbatch 용량을 함께 확보
- 네이티브 `encode` 호출 전에 실제 컨텍스트 용량을 확인하고, 불일치는 복구 가능한 오류로 반환
- 짧은 입력에 설정의 최대 컨텍스트 크기만큼 배치 메모리를 미리 확보하지 않도록 처리
- 한국어·영어 장문 본문과 검색어, 컨텍스트 잘림, 혼합 길이 배치의 실제 모델 회귀 예제 추가

### 검증

- Rust 단위·통합 테스트 52개, 화면·IPC 테스트 12개 통과. 별도 모델이 필요한 OCR 테스트 1개는 기본 실행에서 제외
- 고정 EmbeddingGemma 2 Q8_0로 512·4,096 컨텍스트에서 장문·잘림·혼합 배치 12개 검사 통과. 한국어 1,200자 청크는 실제 3,197토큰이며 4,111토큰 입력은 기본 한도인 4,094토큰까지 처리
- 총 14개 임베딩 벡터의 유한값·768차원·정규화 검사 통과, 기존 검색 관련성 평가 8개 통과
- v0.4.3이 종료되던 동일한 가상 장문을 수정본에서 색인 완료(오류 0), 긴 자연어 검색 결과 1개 및 변경 없는 파일의 증분 건너뛰기 확인
- 실제 설치 앱 v0.4.4에서 ‘다시 색인’ 버튼으로 변경한 긴 한국어 문서 색인 후 새 본문 표식 검색 결과 1개 확인
- 설치 앱 화면에서 1,200자 검색어 검색 완료와 결과 1개, 본문 조각·벡터 각 3개 확인
- Windows 설치 파일로 업데이트 후 설치된 파일 761개의 SHA-256 일치, 기존 색인 DB·WAL 파일 해시 보존 확인

기존 색인과 모델 설정을 유지한 채 설치 파일로 업데이트할 수 있습니다. 이미 업데이트한 PC에서는 앱을 다시 열고 **다시 색인**을 누르세요. 중단됐던 파일을 다시 처리하며, 모델을 다시 다운로드하거나 색인 DB를 삭제할 필요가 없습니다. 앱과 설치 프로그램은 코드 서명하지 않았습니다.
