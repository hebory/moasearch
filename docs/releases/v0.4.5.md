# 모아검색 v0.4.5 — 중복 분석 재사용과 색인 완료 상태 개선

파일이 많은 실제 폴더에서 색인을 끝까지 실행하고 자연어 검색까지 검증했습니다. 생성본·의존성 폴더의 파일 목록을 유지하면서 원본 문서의 내용 검색을 우선합니다.

- 기본 `_site`, `temp`, `vendor` 폴더는 파일명·경로만 색인합니다. **AI 설정 → 파일명만 색인할 폴더**에서 목록을 바꾸거나 비울 수 있습니다. 변경 후 다시 색인하면 적용됩니다.
- 일반 폴더를 먼저 처리해 기존 분석 결과를 원본에 재사용한 뒤, 파일명 전용 폴더의 기존 본문·벡터를 정리합니다. 원본 파일은 수정하거나 삭제하지 않습니다.
- 동일 파일의 OCR·추출·임베딩과 동일 본문 조각의 임베딩을 재사용합니다. 파일·리더·확장자·모델·컨텍스트 한도를 구분하고, 손상된 캐시는 다시 처리합니다.
- **EmbeddingGemma 2 Q8_0**는 가용 CPU 수 안에서 최대 8스레드를 사용합니다.
- 정상 완료·일부 실패·오류 중단·취소를 구분하고 최종 확인·저장·건너뜀·오류 수를 화면에 남깁니다. 긴 파일은 본문 조각 진행률을 표시합니다.
- 긴 자연어 검색문에서도 결과 제목이 버튼을 압축하지 않도록 배치를 개선했습니다.

### 검증

- Rust 단위·통합 테스트 69개와 화면·IPC 테스트 16개 통과. 별도 OCR 모델이 필요한 테스트 1개는 기본 테스트 실행에서 제외했습니다.
- 실제 EmbeddingGemma 2 Q8_0로 장문·입력 한도·혼합 배치 및 기존 관련성 평가 통과
- 가상 장문 복사본 8개 추가 색인: 기존 55.14초 → 재사용 적용 후 0.29초, 복사한 임베딩 BLOB과 원본의 차이 0건. 전체 초기 색인의 속도 비율을 뜻하지 않습니다.
- 실제 이미지·PDF OCR 및 HWP/HWPX 복사본 8개 색인: 오류 0건, 4개 파일의 분석 결과 재사용 및 HWP 본문 검색 확인
- 파일명 전용 정책 전환 시 기존 생성본의 벡터를 일반 폴더 파일에 보존하고, 생성 폴더의 본문·벡터·재사용 키만 제거하는 실모델 검증 통과
- 등록 폴더 전체 14,082개 색인 완료: 저장 13,809개, 변경 없어 건너뜀 273개, 오류 0개. 파일 1,198개·본문 조각 12,539개의 결과를 재사용했습니다.
- 실제 프로젝트 폴더 14,074개를 파일 목록과 독립적으로 대조: 누락·크기/수정 시각 불일치·추가 행·오류 모두 0건, DB 무결성 `ok`
- 파일명 전용 12,248개는 본문·벡터 0개, 원본을 포함한 전체 본문·벡터는 각각 13,450개
- 실제 원본 기능에 근거한 자연어 검색 6건 모두 관련 원본 문서가 상위 5개 안에 표시됐으며 CLI 실행 시간은 1.30~1.69초였습니다. 설치 앱에서도 자연어 입력과 원본 미리보기를 대조했습니다.
- 변경 없는 전체 14,082개를 다시 확인해 전부 건너뛰고 오류 없이 완료한 화면 및 CLI 1.98초 재확인
- 최종 Windows 설치 후 파일 761개, 포터블 ZIP 파일 762개의 SHA-256 일치 및 기존 색인 보존 확인

성능 수치의 조건과 범위는 [성능 기록](../performance.md)에 있습니다. 개인 폴더 경로와 원문은 릴리스에 포함하지 않았습니다. 기존 모델을 다시 받을 필요 없이 설치 파일로 업데이트할 수 있습니다. 앱과 설치 프로그램은 코드 서명하지 않았습니다.
