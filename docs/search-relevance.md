# 검색 관련도 정책

모아검색은 파일 이름·경로와 본문에서 찾은 문자 일치, 그리고 EmbeddingGemma 2 Q8_0의 의미 유사도를 함께 사용합니다. 이 신호들은 서로 다른 근거이므로 결과에는 `파일명·경로`, `본문 키워드`, `소스코드 파일`, `의미 유사`와 같이 실제 일치 근거를 표시합니다. 검색어를 입력하는 동안 이전 검색 결과는 바로 비워서, 새 검색이 끝나기 전에 이전 결과를 새 결과로 오해하지 않게 합니다.

## 소스코드 검색어

`소스코드`, `소스 코드`, `source code`, `source-code`처럼 정규화 후 정확히 일치하는 별칭은 소스 파일 확장자 목록과 별칭 전체 표현의 문자 검색을 사용합니다. `소스 코드`를 `소스`·`코드`로 나누어 `프로젝트 코드` 문서를 끌어오지 않습니다. 이 의도 검색에는 임베딩 의미 유사 결과를 더하지 않습니다. 따라서 단어 일부만 의미상 비슷한 HWP/HWPX 문서가 소스코드 결과에 섞이지 않습니다. 반면 소스코드 별칭이나 다른 검색어가 파일 이름·경로 또는 본문에 실제로 들어 있는 문서는 파일 종류와 관계없이 문자 일치 결과로 남습니다.

문장형 검색은 이 별칭 처리로 바꾸지 않습니다. 예를 들어 `프로그래밍 구현 파일`은 일반 하이브리드 검색으로 처리하고, 코드 파일이나 관련 설명 문서가 의미 유사 결과가 될 수 있습니다.

## 하이브리드 검색의 문자 근거

하이브리드 모드에서 여러 단어로 된 검색어에 한글 한 글자 항목과 더 긴 항목이 함께 있으면, 한글 한 글자만의 일치를 문자 검색 근거로 사용하지 않습니다. C·R 같은 한 글자 영문 식별자는 유지합니다. 예를 들어 `이사 나간 뒤 맡긴 돈을 돌려받는 조건`에서 `뒤` 한 글자만 우연히 본문에 포함된 요리 문서를 키워드 일치로 올리지 않습니다. 한 글자만 입력한 검색어의 부분 문자열 검색과 키워드 전용 모드의 동작은 유지합니다.

키워드나 파일명·경로로 일치한 결과는 의미 점수 기준 때문에 제거하지 않습니다. 의미 검색이 임베딩을 지원하지 않거나 사용할 수 없을 때에도 가능한 문자 검색 결과를 유지합니다.

## 의미 유사 결과 기준

현재 의미 전용 결과는 다음 조건을 모두 만족해야 합니다.

```text
유사도 >= max(0.70, 최고 후보 유사도 - 0.05)
```

즉 절대 하한인 `0.70`보다 낮은 후보는 제외하고, 최고 의미 후보보다 `0.05` 넘게 뒤처진 후보도 제외합니다. 키워드 또는 파일명·경로 근거가 함께 있는 결과에는 이 기준을 적용해 해당 문자 일치를 지우지 않습니다.

이 값은 현재 고정 모델인 **Google EmbeddingGemma 2 Q8_0**와 모아검색의 일반 파일 검색 동작을 대상으로 둔 보수적 휴리스틱입니다. Google이 제시한 보편적인 관련도 임계값이 아니며 모든 질의와 파일에서 무관한 결과를 완전히 막거나 관련 문서를 빠짐없이 찾는다는 보장도 아닙니다. 특히 기준을 높이면 오탐은 줄 수 있지만 표현이 다르거나 점수가 낮은 관련 문서를 놓칠 수 있습니다. 검색 점수는 검색 순위와 후보 선택을 위한 cosine 유사도이지, 정답일 확률이나 관련도 백분율이 아닙니다.

Google의 [EmbeddingGemma 2 모델 카드](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)는 문서 검색을 비대칭 검색으로 설명하고 검색 질의와 문서에 맞는 task prefix를 안내합니다. [Sentence Transformers 추론 안내](https://ai.google.dev/gemma/docs/embeddinggemma/inference-embeddinggemma-with-sentence-transformers)는 cosine 유사도를 의미 유사성 척도로 소개하면서, 예시의 무관한 문장 쌍도 `0.6880`을 얻는다고 보여 줍니다. 따라서 이 숫자를 확률처럼 읽거나 임의의 보편 cutoff로 간주하지 않습니다. 두 자료는 모아검색에 적용할 단일 관련도 threshold 또는 재순위화 정책을 정하지 않습니다.

## 회귀 평가와 한계

관련도 조정 시 저장소의 합성 평가를 실행할 수 있습니다.

```powershell
cargo run --release --locked --example evaluate_relevance -- .moasearch-rust-dev/models
```

평가는 격리된 합성 파일 12개와 8개 질의의 추출 본문 및 고정 임베딩 모델을 대상으로 합니다. 원시 cosine 순위와 실제 하이브리드 결과를 비교해 질의별 상위 파일, 매치 근거와 의미 전용 후보의 유입을 확인하는 용도입니다. 수정 전 v0.4.2 검색 정책과 수정본을 같은 가상 본문으로 비교했습니다. 예를 들어 `소스코드` 기준선에는 무관한 HWP/HWPX가 semantic-only로 나타났고, `해왕성의 대기 성분`처럼 합성 자료에 답이 없는 질의도 여러 무관 문서가 상위에 포함됐습니다. 이는 raw cosine 상위 목록만으로 결과를 노출하면 의미 있는 검색 결과가 된다고 볼 수 없음을 보여 줍니다.

합성 자료의 평가 결과는 사용자의 실제 파일, OCR 품질, 문서 길이·언어·주제 분포를 대표하지 않습니다. 따라서 평가 실행을 통과했다는 사실만으로 실제 전체 문서 집합의 검색 품질을 보장할 수 없습니다. 관련도 정책이나 모델이 바뀌면 알려진 질의와 기대 결과를 사용자의 데이터와 분리된 고정 fixture에서 반복 평가하고, 실제 사용에서 발견된 오탐·누락 사례는 비식별화된 회귀 사례로 추가해 threshold 및 단어 처리 규칙을 재검토합니다.
